# 2026-10-23 Quno 决策 6 修订：dsh-thread 直接退役，非能力替换

## 修订

修订 `2026-10-23-quno-product-decisions.md` 第 6 条（旧 note 不改写，以本文为准）：

- **旧表述**：Quno 委派子任务是 thread_handoff 的能力超集，未来以 Quno 替换 dsh-thread 的插件与能力。
- **新表述**：thread_handoff 的跨会话交接功能**整体不需要**。dsh-thread 直接退役下船，Quno **不做能力承接**——不存在能力平价对照、平价验收门槛，也没有「替换体验」一说。

## 对开发说明的影响（已落地到 `docs/quno-bot-design.md`）

- §4.1：主对话不挂 `thread_handoff`，措辞改为「功能整体不需要、直接退役、不做能力承接」。
- **撤销** §5.5「草稿模式与结构化交接（thread_handoff 替代形态）」整节——它是为平价 thread 而设的，功能本身不需要，草稿确认形态一并撤销；委派子任务只剩 §5.1 的自决执行形态。
- §5.1 保留一条有独立价值的工程继承：子会话继承主对话 preset/模型时 append `model/selection` 事件而非 `selectModel`（rc.7 教训与 thread 退役无关，保留）。
- §16.1 从「能力平价与退役」改写为纯退役路径：时机不依赖 Quno 进度、下船事务（只认桌面自装副本）、用户数据只读保留不迁移、manifest 清理与发版、回退。
- §17 第 6 行同步，原「能力超集/替换」表述作废。

不影响其他六条产品决策。
