# Runtime pin: official 0.1.2-rc.1 + zw.1

Pin `runtime/revision.json` at fork tag `v0.1.2-rc.1+zw.1` (`1b138a9e5b403a00f942cc90d3650d6584926cdc`, merge of [aka-danielZhang/deepseek-harness#13](https://github.com/aka-danielZhang/deepseek-harness/pull/13)). npm layer `@crazx/*@0.1.2-rc.1.zw.1` is published (workflow `33777179514`).

This supersedes the alpha.5 pin in [`2026-09-03-runtime-0.1.2-alpha.5.md`](./2026-09-03-runtime-0.1.2-alpha.5.md).

## Official

`dsh-v0.1.2-rc.1` is the first 0.1.2 release candidate. It rolls up the 0.1.2 alpha line; the plugin-facing breaks we already absorbed on alpha.4/5 still hold:

- `Session.events` → `seq` / `eventAt()` / `snapshotEvents()`; `SessionSeq` vs `SessionLogOffset`.
- `send_message` replaces one-way `report`.
- Projection-cache cross-version read compat (alpha.5).
- Host `session.create` still takes `agentPreset` at birth; client `ISessions.create` still drops it, so Thread continue() stays on `ctx.remote.session`.
- `dsh-client-runtime` is still unpublished on 0.1.2 (last registry version `0.1.1-rc.2`).

Intel/x64 policy is unchanged (upstream still did not ship it).

## Fork

Official `dsh-v0.1.2-rc.1` merged onto `aka-danielZhang/deepseek-harness` with +zw patches kept. `publish-fork --list --base 0.1.2-rc.1` is the same 11 packages. Guard `todo-completion-guard` still reads `snapshotEvents()`.

## Oh My DSH plugins

No new compile-break APIs versus the alpha.5 pin. Exact `@deepseek-ai/dsh-*` pins move to `0.1.2-rc.1`. `dsh-mcp-settings` aliases `@deepseek-ai/dsh-mcp-client` to `@crazx/dsh-mcp-client@0.1.2-rc.1.zw.1`. `scripts/source-deps.mjs` follows the same split.
