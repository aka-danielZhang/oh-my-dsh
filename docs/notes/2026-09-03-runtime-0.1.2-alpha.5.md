## Official

- **alpha.4** (`dsh-v0.1.2-alpha.4`): `send_message` replaces one-way `report`; model catalog search/filter + profile headers; UI polish; long-session render cost; `web_fetch` default for Python SDK / Headless / ACP / custom profiles; Web PTC drops default `workflow`; **`Session.events` → `seq` / `eventAt()` / `snapshotEvents()`**; **`SessionSeq` vs `SessionLogOffset`**.

## Oh My DSH plugins

- `dsh-thread` host gateway: `session.events` → `session.snapshotEvents()` (alpha.4 compile break). Client half: `ConnectionHandle.api.sessions.create/rename` is gone; continue() talks to `ctx.remote.session` and keeps `agentPreset` on create (Host still requires it at birth). `ClientContext` type-imports stay on last-published `@deepseek-ai/dsh-client-runtime@0.1.1-rc.2` because 0.1.2 deleted that package.
- `dsh-llm` renamed `CallId` → `ToolCallId` (compaction + fs-observation-log tests). Headless `Modal` forbids `closeLabel` (desktop-bridge update dialog). `TokenMeter` now registers `sessionProjections` at construct; engine tests stub that service. `dsh-sandbox` must be the same baseline as `dsh-llm` (`assertNever` left llm; an rc.2 sandbox against alpha.5 llm fails to load).
- Other plugin `@deepseek-ai/dsh-*` exact devDependency pins move to `0.1.2-alpha.5`. `dsh-mcp-settings` aliases `@deepseek-ai/dsh-mcp-client` to `@crazx/dsh-mcp-client@0.1.2-alpha.5.zw.1` (fork `mcp-client/status` event).
- `scripts/source-deps.mjs` REGISTRY follows the same split.
