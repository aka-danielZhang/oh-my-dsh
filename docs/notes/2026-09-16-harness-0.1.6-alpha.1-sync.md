# Harness `0.1.6-alpha.1` 上游同步（2026-09-16）

大版本跳跃（800 提交）的首次自动化同步。完整落地记录见 `docs/harness-bump/0.1.6-alpha.1/README.md`；本 note 记三个可复用结论。

## 结论一：上游 0.1.6 重命名/重构了 MCP SDK 消费面

- SDK 从 `@modelcontextprotocol/sdk/*` 换成新包 **`@modelcontextprotocol/client`@2.0.0**（ESM）；`dsh-mcp-client` 的 lib 外部化引用它。
- 客户面：`getServerCapabilities()` + `listTools()` 取代 `request('tools/list')`；listChanged 从 `setNotificationHandler` 改为构造参数 `onChanged`（fire-and-forget，测试要 `vi.waitFor`）；transport 构造收进 lib 内联 `createTransport`。
- 凡直接/间接测到该链路的测试套都受影响：fork `status.spec.ts`、`dsh-mcp-settings` manager/inventory 两套。

## 结论二：externalized CJS 的 mock 只剩 importer 边界 alias 一条路

`vi.mock` 与 vite `resolve.alias` 对「externalized CJS require(esm)」链路全部失效（真 SDK 被拉起，假件零实例）；`deps.optimizer` 会把真依赖烤死；`server.deps.noExternal` 在 vitest 4.1.8 未生效。**在 importer 侧 alias 替换整个包**（本例 `@deepseek-ai/dsh-mcp-client` → `tests/mcp-client-fake.ts`）是唯一稳定拦截点。假件要过 cordis 的四道坎：`Config["~standard"].validate`（Standard Schema 接口）、`inject` 声明（缺了 `ctx.tools` 拒访）、工具 output 需 `{ schema, render }`、apply 返回 disposer。

## 结论三：0.1.6 的 dsh-tools 新增 dsh-sandbox peer

`dsh-tools@0.1.6-alpha.1` 的 lib import `@deepseek-ai/dsh-sandbox`（peer），`autoInstallPeers: false` 下凡是锁了 dsh-tools 的插件都要显式 devDep 供出（`dsh-mcp-settings`、`dsh-ohmymemo` 本轮各补一处）。

## 结论四：agent/session-start 事件在 0.1.6 被移除

0.1.6 上游移除 `agent/session-start`，其语义并入 **`agent/created`**（serial，负载 `{ agent, source, signal? }`，覆盖新建/恢复/清理/压缩——超集）。唯一消费方 `dsh-thread` 的 gateway 改听 `agent/created`（reconcile 幂等，额外触发无害），bump 0.3.0-rc.2。
